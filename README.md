# Domino

**Three hospitals. Twelve families. No shared database.**
Kidney-swap discovery across hospitals with Flower Agents: each hospital's agent answers a fixed catalog of questions from its own private records and rulebook; a coordinator agent on Flower SuperGrid builds the exchange from categories only. Code decides (compatibility, matching, consensus, timing, audit); models read and explain. A surgeon approves every plan.

> All patients, donors and hospitals are fictional. Synthetic data. Not a clinical tool.

Collaborative Agent Hackathon @ Stanford · 2026-09-29.

## How to run the demo

```bash
git clone https://github.com/hrihaan19/collaborativeagentshack.git && cd collaborativeagentshack
python3.11 -m venv .venv && source .venv/bin/activate     # 3.11+ (3.14 works)
pip install -e ".[dev]"
pytest -q tests                                            # 10 passed: edges, loop, swap, chain, timing, measured keyword score
scripts/start-projector.sh                                 # http://localhost:7800/projector
```

| Machine | Opens | Role |
|---|---|---|
| Mac 4 (projector) | `/projector` (press **F**) | drives the beats; hosts consoles and `/give` |
| Mac 3 (Riverbend) | `http://<mac4>:7800/console/riverbend` | the surgeon's approval card (beat 5) |
| Macs 1–2 | `/console/alder`, `/console/harbor` | hold replies (beat 5) |
| a phone | `/give` (QR on beat 6; set `PUBLIC_URL` in `.env` to the LAN or tunnel URL) | starts the chain |

**Keys:** → / Space next · ← back · R reset · S finish beat from script · G fire the chain · B Harbor Point offline · F fullscreen · 1/2/3 consoles · M scripted ↔ live · H help. Beat-by-beat script with the "say" lines: [`docs/demo-script.md`](docs/demo-script.md).

**Modes.** The badge always tells the truth.
- **REHEARSAL** (default): scripted, zero network. Every event object is generated by the same matching code from `data/domino-data.json` (`domino/story/script.py`) — plans, chains, legs and times are computed, not typed.
- **LIVE**: press **M**. On beats 3/5/6/7 the projector runs `flwr run . supergrid --run-config 'phase="search|approve|chain|schedule" …' --stream` inside `flower/` and renders only real `DOMINO_EVENT` lines. After 25 s of silence it finishes the beat from the script and the badge drops to REHEARSAL. Runs are logged to `runs/`.
- Replay mode is not built.

## What never crosses the wire

`flower/domino_app/wire.py` allowlists every message kind in both directions and rejects unknown keys, any key matching *name / note / citation / antigen / cPRA / calendar / availability / quote / chart*, and free text over 80 characters. Donor HLA is allowed only in coordinator→hospital `compat` asks. The canary question (`patient_names`) is refused **before** any record is read (tested). A ledger records what each hospital ever disclosed: field names and bytes.

## Flower agents (`flower/`)

One `AgentApp` (`domino_app/agent_app.py`) runs in two places and detects its role from `agent.grid.tools()`: `get_nodes/push_messages/pull_messages` → coordinator; `push_reply_message` only → hospital.

- `coordinator.py` — phases `search`, `approve`, `chain`, `schedule` (each one `flwr run`): hello → compat+readiness → canary → code plan → Endeavor explanation (`flower-endeavor-v1.0`, fallback `openai/gpt-5.6-sol`, template if no model) → audit → `phase.end`.
- `hospital.py` — the catalog (hello, compat, readiness, canary, approve, hold, windows, leg); everything else is refused. Readiness = BM25 retrieval (`retrieval.py`) over that hospital's rulebook + charts + `decisions.md`, then the local model with strict JSON, quotes checked in code (one rulebook + one chart citation for any non-ready answer), keyword rules as fallback (`source: rules`). Approve/hold wait for the human on the console.
- `audit.py` — code checks every id / hospital / time / count in an explanation against the plan and ledger; a second model does the same. Either failing → `audit ok:false` → the consoles' Approve is locked.
- `events.py` — `DOMINO_EVENT {json}` on stdout + `agent.events.emit`; hospital-only events POST to the local console (127.0.0.1:7800/events), never through the Grid.

```bash
cd flower
uv sync                                    # or: pip install -e .
uv run pytest -q tests                     # 6 passed, offline, <1 s: wire, canary, retrieval, all four phases via a fake Grid
uv run python scripts/split-data.py        # data/<hospital>/records.json + docs/, data/public-donors.json (no names)
uv run flwr build                          # FAB contains code only (checked: 0 data files)
```

Each hospital Mac: `scripts/setup-supernode.sh alder|harbor|riverbend` (registers the SuperNode on SuperGrid, copies only that hospital's folder to `~/domino-data/<h>`, exports `FLWR_MODEL_API_ENDPOINT` for local Ollama, starts `flower-supernode`). Coordinator Mac: `scripts/run-phase.sh search` etc., or simply LIVE mode on the projector. Publish: `uv run flwr login supergrid && uv run flwr app publish .`.
