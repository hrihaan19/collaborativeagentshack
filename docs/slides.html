01 The person

Meet Maria.

She's 46. Her sister Elena wants to give her a kidney.

Elena is blood type B. Maria is A. The kidney can't go to her. Forty miles north at Harbor Point, James needs a kidney and his wife Priya is type A. He's type B. Priya could give to Maria. Elena could give to James. Nobody knows, because nobody can see both charts.

02 The gap

The match is in another hospital's files.

every chart→ upload→ one central registry→ a matcher that sees everything
"Patient names, charts, antibody lists and donor notes never leave Harbor Point." Harbor Point rulebook HPH-LD-12 · §3.1
Every program keeps its own list, its own donor notes and its own rulebook. The answer to Maria's question lives in files that are not allowed to move.
The usual fix is one shared database: every hospital hands over every record before a single question can be asked.
03 The inversion

Domino sends the question, not the data.

One form out. Five fields back. Nothing else crosses.

Alder's coordinator builds a screening form from its own pod: opaque tokens, blood types, donor HLA, unacceptable antigens, a window, four questions. No names. Flower carries it to each hospital's SuperNode as a real message. Each agent answers from its own pod and returns exactly five fields, every one a category, checked against an allowlist on both ends.

04 The reasoning

Each agent thinks where the data lives.

receive form→ open own pod→ retrieve→ screen in code→ reply · 5 fields
It opens its own pod, the only directory it can reach, and its private console lists every file it reads. The projector never sees them.
Retrieval pulls the pairs, notes and rulebook sections that fit the form. Then code screens every pair both ways: blood type and virtual crossmatch. Code decides.
Harbor Point finds James and Priya, checks Priya's leave against the window and its own §1.1 and §1.2: ready. Riverbend finds no pair, reads its §3.1, and widens the search.
An extra field, a forbidden word, free text where a category belongs: refused before it is sent. Tested on both ends.
05 The human

A surgeon signs. A person confirms.

Alder reviews the replies in code and proposes the exchange: Elena to James, Priya to Maria. Its own rulebook, §2.4, says nothing is scheduled without a signed approval form. So the surgeon signs one, and it goes on the page.

PROPOSED→ decode the form's QR→ measure the ink→ match id + token to the live run→ REVIEWED
Confirm approval unlocks only when every check passes and the surgeon ticks the acknowledgement. The tap is the confirmation.
An unsigned form fails. A form for the wrong candidate fails. Both ship with the demo, so you can watch them fail.
06 The result

Two transplants. No shared database.

Maria gets Priya's kidney. James gets Elena's. Three hospitals ran one search together, a surgeon approved it, and none of them ever opened another's files.

The data never moved. The question did.
